What the standards actually do

The listings people use every day agree on three things, and the cards I shipped broke all of them. Everything is left-aligned in a stack; nothing is right-aligned inside a card except a single badge. Each line has one job: a name line, a description line, a facts line, and each card has the same number of lines so heights match. Icons are few: one kind glyph, then text with dot separators, not a cluster of marks fighting the name.

  • GitHub repository cardname · one visibility badge at the right / description / footer: language dot, stars, forks, "Updated 3 days ago". Two per row on a profile.
  • Hugging Face model cardtask icon · owner/name / one muted line: "Text Generation • Updated 3 days ago • ↓ 1.2M • ♥ 2.3k". Private shows a lock, public shows nothing.
  • GitHub repositories listrows on hairlines: name + badge / description / meta with dots; one action at the right. The page every developer already reads.

Also from the standards: your own repositories are a view ("Your repositories" vs "Explore"), never a per-card badge. So the switch becomes Yours · Public and the "yours" pill disappears. Provider glyphs leave the title and become words in the description, where Hugging Face puts the task.

E1 GitHub card four across, four lines each

Line 1: kind glyph, name, one outline badge for visibility. Line 2: description in words ("Git project · Codex, Claude"). Line 3: facts with dot separators and small glyphs. Line 4: who pushed it and when, the way GitHub's footer says "Updated 3 days ago". Every card has four lines, so every row is one height.

  • Name gets 170px. The badge is the only thing beside it.
  • Left-aligned stack. Nothing collides because nothing is pinned right except the date.
  • Reads top-down. What, what kind, how much, who and when.
  • Four lines. ~112px per card; three rows before scrolling at this height.

E2 Hugging Face card three across, two lines each

Line 1: task icon, then owner / name in one run, a lock only when private. Line 2: one muted line with dot separators: kind, pushed date, facts. It is the densest honest card there is: two lines, nothing pinned right, and the owner is part of the name the way it is on the Hub.

  • Two lines. The shortest card that still says who, what, and how much.
  • Owner in the name. "Rika321 / HorrorGame" is how people cite it elsewhere.
  • No badge for public. Public is the default state; only private earns a mark.
  • Three across. Owner + name need the width; four across would cut names again.

E3 GitHub list rows on hairlines, one column

The repositories page itself: rows in one tile, each with name and badge, a description, and a facts line with dots; the pusher and date at the right, where GitHub keeps its one action. Rows never fight for width, so nothing is ever cut, and the eye runs down one column of names.

  • Nothing truncates. Names and descriptions have the whole width.
  • Scans like a table. Facts line up under each other down the page.
  • Most familiar. Every developer has read this page.
  • Not a grid. Five rows use the height four-across cards would give ten.

Where I would land

E1, the GitHub card. It keeps four across, and it is orderly for the reason GitHub's is: one badge on the name line, then a stack of single-purpose lines, all left-aligned, always four of them. The provider marks and the "yours" pill are the two things that made the last version messy, and the standard simply does not put them on a card: providers become words in the description, and "yours" becomes the view you are in. E3 is the answer if you would rather trade the grid for zero truncation; E2 if two-line density matters more than four per row.
