0 · The cleanup seven elements removed; every job they did is re-homed

The unlock is one move: the current storage stops being a list row and becomes the menu's header — the Chrome-profile / GitHub “signed in as…” shape. Once position says “this is the one you're on”, the checkmark, the radio semantics, the This storage · caption and the section header are all saying something the layout already says. Two columns survive: an icon gutter and the words.

The removal ledger

  1. 1 “STORAGE · 1 linked” header — removed. The crumb you just clicked is the menu's label, and a one-item list is its own count. Chrome's profile menu and GNOME primary menus carry no title either. The tally's one real job — “there are others” — is done better by the Switch-to section simply existing. GNOME HIG · Chrome profile menu
  2. 2 Checkmark gutter and radio semantics — removed. The current storage is promoted out of the list into a header block, so “which one am I on” is answered by position, not by a mark. Other storages become plain switch commands. This is the GitHub “Signed in as…” / Chrome current-profile shape, and it deletes a whole column from every row. Chrome · Slack · GitHub user menu
  3. 3 Kind tags “local / s3” — removed. The drive/cloud glyph already says it, and the second line (a path, or “Bucket · …”) says it again. A third telling earned a column; two are enough. redundancy — same fact, three encodings
  4. 4 “This storage · Local storage 1” caption — removed. It repeated a name visible twice already — in the header block directly above and in the crumb the menu hangs from. Proximity now does the scoping: verbs directly under the header act on the header. The name still appears where it must: inside the unlink label and its confirm. Gestalt proximity · Apple HIG
  5. 5 “Reveal in Finder” (storage) — removed. My own addition in the first draft, not a shipping command. It rides along inside Storage settings, one hop away. The project menu keeps its Reveal — that one ships today. YAGNI — don't grow the menu to justify the band
  6. 6 “2 available” count — removed. The picker that Link storage… opens shows the candidates anyway; the count bought a trailing column for a number you act on once a month. The one state that matters — zero — keeps its explanation, as a disabled row with a reason (§2). NN/g — explain the disabled, not the ordinary
  7. 7 “Files stay on disk” sub-line — moved, not lost. The ellipsis on Unlink… promises a confirmation, and the confirmation is where the blast radius now lives, stated once at the real decision. Menu rows drop to one line each. NN/g — state consequences at the point of commitment
Net effect. Four grid columns → two. Nine text styles in the menu → four (name, path, section label, danger). The 1-linked menu: 7 visual units → 5. Row grid, heights, danger and disabled conventions are unchanged from the options page — this is subtraction, not a new system.

1 · Three cuts how far to take the knife — pick one

Same rulebook, same verbs, three depths of cut. They differ on exactly two questions: does the current storage stay a list row or become the header, and how much data do rows carry. Everything after this section is drawn as A1.

A1 · Header-first — recommended

Local storage 1~/Desktop/project/myconfstorage
Switch to
Current storage is the header; verbs sit right under it, so no caption and no checkmark exist at all. Two columns, zero ARIA state to maintain. The Chrome-profile / “Signed in as…” shape.

A2 · Switcher-first

This storage
Keeps today's mental model: a checked list first, switching stays the top rows. The macOS-menu shape. Price of familiarity: the tick column returns on every row, and because the current storage is just a checked row, a small “This storage” caption has to come back to scope the verbs. One column and one label heavier than A1.

A3 · Names only

Local storage 1
Switch to
A1 with the data lines cut too: no paths anywhere, every row one line, the menu shrinks to 248 px. The path moves to the crumb's tooltip and Storage settings. Cleanest possible — but two storages with similar names become indistinguishable here, and the header stops telling you which folder you're syncing to. Choose only if storage names are kept unique and meaningful.
Recommendation. A1. It deletes the most chrome without deleting data (A3's cut) and without re-buying the tick column and caption (A2's price). If switching storages turns out to be the dominant action, A2 is the fallback — it is the same menu with the bands reordered.

Against SyncPathBar as shipped: the menus stay PathBarMenuGroup data. New needs: a header-block item kind, a checkbox item kind (trailing check), aria-disabled rows with reason lines, type-ahead, roving tabindex, and focus-return. Gone from the earlier draft's needs: the tick gutter, the split heading slot, and radio-state plumbing — the cleanup removes code, too.
