Direction C, in the app's own grammar

Three card faces the desktop already ships, applied to the home page. All three cast the 3px shade on the card and 2px on controls, use the app's pixel glyphs for kind (git folder, folder, bulb for a skill, paw for a pet), its ChatGPT and Claude marks for providers, Baloo 2 for names, and mono for figures and dates. The controls above the grid are the desktop's: the segmented switch, pill buttons that sink when pressed, an ink-edged field. No note, no footer.

C1 Picker cards the desktop's Projects and Catalog landing

The card that opens a project in the app: glyph, name, marks on the first line, a mono location line underneath, and a detail line of facts. Three across at this width, every card in a row the same height. The provider marks and the pusher sit at the end of the title, where the desktop keeps its marks.

  • Same face as the app. Someone who opens projects in Mallard recognises the door.
  • Three lines carry everything. Identity, location, facts, each in its own voice.
  • Wide grid. Three across; skills and pets sit beside projects without a second layout.
  • Location line needs a real identifier. Here it carries the version and pusher; the app puts a path there.

C2 Activity cards the desktop's Git history rows

The session card from your screenshot, one per repository: a title line with the kind glyph and an end cluster of marks and a chevron, then a meta line of mono readouts with the date at the far end. Two across; the meta line reads as a table down the column.

  • Figures line up. Sessions, files, size, and date sit in the same place on every card.
  • Compact. Two lines per card; ten repositories fit in one screen.
  • Chevron says "opens". The row is a door, as in the app.
  • Less identity. The name is set smaller than in C1 and there is no room for a location line.

C3 Framed tiles the desktop's file activity face

A framed glyph tile at the left, its own ink edge and 2px shade, then name and a one-line description, then the marks stacked at the end. The frame gives each kind a badge that reads before the name does; two across.

  • Kind reads first. Bulb, paw, folder: the frame makes the glyph a badge.
  • One description line. Plain words instead of icon readouts.
  • Room for the end cluster. Marks above, date below, nothing crowds the title.
  • Heaviest ink. Two boxes per card; the grid gets busy past ten items.

Where I would land

C1. It is the card the app already uses for the same job, opening a project or a catalog item, so the site and the desktop share one door. Three across gives skills and pets a home without a second layout, and the mono location line is where the version and pusher belong. C2 is the choice if figures matter more than names; C3 if kind should read before anything else.
