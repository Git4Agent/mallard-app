Three ways to read the list

Twelve real repositories from the running service, with their real figures. Eight are catalogs with no sessions, and only two carry a GitHub description — that lopsidedness is the design problem, so every direction below is drawn with it rather than around it.

All three reuse the shipped palette and box grammar. The figures are the ones the listing API already returns and the card currently throws away: summary.conversations, summary.files, summary.resources.

A — Ledger cards

The shipped card, with the figures row D2 recommended and never got. Three across, nothing moves except the footer.

  • Keeps the grid, the description slot, and the density you already have.
  • Adds two fixed figure slots, so sessions and files line up down the column.
  • Costs the pusher's login — the avatar stays, the name goes, to buy the room.

B — Register rows

What GitHub actually does, and what your screenshot shows: one full-width row per repository, with the description given the room to be read.

  • Keeps the most room for a description — a full line of prose, not a clamped column.
  • Adds a real Star button carrying its own count, as GitHub has.
  • Names the kind only on hover; the glyph carries it, so the row never spells it out.
  • Says nothing else. No counts. The row is the name, what it is for, who touched it and when.
  • Costs density: eight rows fill the screen where twelve cards fit now.

C — Index rows

The Hugging Face answer: the address leads, the numbers carry the row, prose is demoted to one line. Built to scan fifty, not to read twelve.

  • Keeps every repository visible at once; two across, four lines each.
  • Adds the full owner/name address, as Hugging Face shows it.
  • Costs the description — one clamped line where there is one, and nothing where there is not.

Where this landed

B, chosen, and kept quiet. Two things left the row after the first pass: the spelled-out kind, which the glyph already carries and its tooltip now names, and the session and file counts. What remains is the name, the description, the providers, who pushed last, and when — the things that tell one repository from another at a glance. Counts belong on the repository page, where there is room to say what they count.

The open question B inherits: only two repositories in twelve carry a description today, so most rows run a line short. Now that the counts are gone, the description is the row's only distinguishing prose, which makes a second source for it worth more, not less — descriptor.description already exists for desktop pets.

One thing to decide before any of them: D2's ledger also carried a size figure (“16.4 KiB”). committed_bytes is only on the Yours listing — the public, starred and profile listings do not return it. So either size is a Yours-only column, or the service starts sending it. None of the three above use it.
