R2 setup — agent bar redesign

The guide row splits into two named routes: Agent setup — the button now opens Claude Code or Codex directly with the instruction as its prompt, and a finished copy can always be copied again — and Manual setup, the guide link beside the fields it introduces. Four arrangements below, rendered over the shipped App.css + RetroTheme.css. Every control works: copies land on your clipboard, Run plays the launch hand-off and fills the field, or jump states with the chips. The Setup guide link is inert here.

Current

one sentence carries both routes; copy is one-shot
  • The manual route's link and the agent route's button share the sentence's tail, so the two routes read as one blob.
  • The button only copies — and after the copy it dissolves into "listening", so there is no way to copy again — nor to cancel the listening — without editing a field to kill the marker first. Pasting and running the agent is left entirely to you.

Option A — split bar

same bar as today, two labelled cells; ▾ holds the other agent + copy
  • Two labelled cells in the one row the bar already spends — the rule and the small-caps labels do the separating.
  • Split button: the visible half runs the default agent (your last choice, here Claude Code); the ▾ menu — the path-bar menu recipe — holds Run with Codex and Copy agent instruction.
  • Below ~760px the cells wrap and the bar becomes Option B for free.

Option B — two rows

a row per route; same split cluster, more room to breathe
  • One row per route: the agent row wears the accent tint, the manual row stays quiet — the loudest 1:1 match to "agent | manual" at the cost of one extra row (~34px).
  • The cluster is the same split button as A; B differs only in how the two routes divide the bar, so the sentence never fights the buttons for width.

Option C — agent band

the band voice from the setup pages; every verb in the open
  • The agent route becomes an accent-bordered band above the fields — the setup-page band voice — with a run button per detected agent plus the copy route, no menu to discover.
  • The manual route stays a slim labelled line directly above the fields it introduces.
  • Costs the most height, and promotes the agent route to the point of reading almost mandatory.

Option D — “or” divider

the sign-in convention: one button per agent, then the manual form
  • The OAuth sign-in convention — one button per provider, an “or” rule, then the manual form — is the most recognizable “automatic above, manual below” split there is; “Run with Claude Code” sits exactly where “Sign in with Google” would.
  • The divider introduces the manual route exactly where the fields start, and carries the Setup guide link.
  • Caveat: the centered composition breaks the card’s left-aligned rhythm, and lifecycle states render centered where the buttons were.

Mechanics shared by all four

  • Run with Claude Code / Run with Codex (new) — persists the draft exactly as Copy does today (same draft-id + revision fencing), builds the same guarded instruction, then opens that agent’s CLI with the instruction as its prompt (Claude Code and Codex both take a prompt at launch). The agent then drives the Mallard CLI exactly as if you had pasted it yourself; Cloudflare sign-in, MFA, and consent still happen in your browser; the page’s existing listener adopts the finished draft into the editable form. Which agents are offered is registration-driven — the provider registry plus a PATH check — never a hardcoded pair, with Copy as the route for every other agent.
  • Launch flavor is one open decision — a terminal window running the agent where you can watch and answer its approval questions, or a silent headless run (claude -p / codex exec) narrated only by the status line here. The instruction asks the agent to request approval before installing anything, which a silent run cannot surface — the mock assumes the visible-terminal flavor; the states here are identical either way.
  • Copy stays repeatable, listening stays cancellable — the copied state keeps a Copy again button and a Cancel beside the listening line instead of dissolving into it. Copy again re-copies the same instruction and flashes green, per the copy-button convention; Cancel clears the marker and returns the zone to idle — today only editing a field does that.
  • Lifecycle unchanged — any field edit still kills the marker and returns the zone to idle; the CLI can only write the exact draft revision it was handed; nothing commits until you press Finish setup. Actions stay disabled until the storage name is set.
  • Scope — new-storage drafts only. A settled storage keeps today’s one-line “Configured…” bar; the connected state here reuses the shipped green voice.

Standards consulted

  • Split button (A, B) — Microsoft Fluent’s SplitButton and Material 3’s split button: the visible half fires the single most common action, the chevron discloses the rest; GitHub’s merge button is the household example. Convention says the visible half should track the user’s last choice — so picking Codex once makes Codex the face of the button. NN/g’s caveat — menu contents are less discoverable — is why C and D keep every verb in the open.
  • Labelled option rows (B) — the option-row list used by repository create/import screens and GOV.UK-style option sections: each route gets one row on equal footing, scanning top-to-bottom.
  • Promoted action panel (C) — the highlighted-path card (GitHub’s Clone panel, onboarding checklists): the loudest treatment, and the only one with room for a run button per agent plus copy without a menu.
  • Provider buttons + “or” divider (D) — the sign-in form convention (provider buttons → “or” rule → manual form) used by virtually every OAuth login page; “Run with Claude Code” maps 1:1 onto “Sign in with Google”, including the provider mark on the button.
  • Repeatable copy feedback (all) — the GitHub/Stripe/MDN docs convention: a copy control flips to a green “Copied” for about a second and stays clickable; it never disappears after one use.
  • Status semantics (all) — waiting/connected lines carry role="status", failures role="alert", matching WAI-ARIA live-region guidance and the app’s shipped notice rules; the running state offers Cancel, per long-operation guidance.
