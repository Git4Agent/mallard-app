0 · Before as it ships today

Two rows of chrome above the list, carrying fourteen controls and readouts — four of which say something another element on the same screen already said.

  3. / Git history

  1. Two overflow menus, same glyph, 90 px apart. The left ⋯ is project and storage actions; the right one is app actions. Nothing in either one says which is which, so the only way to find a command is to open both.
  2. Refresh exists twice. The ↻ button reloads this project's activity and its storage comparison; “Reload app data” inside the right ⋯ reloads everything. Two refreshes in the same corner, neither labelled with its scope.
  3. The second row exists for one control that belongs in the trail. The branch is where you are — the same class of fact as the storage, the repo and the section. Splitting it onto its own line costs a whole row and puts half the answer to “where am I?” below the bar that answers the other half.
  4. The status pills sit next to the buttons that would resolve them, and are not connected to them. “3 local‑outstanding” is exactly “3 threads to Push”. It is rendered as read‑only decoration, in a different visual language, 200 px from Push.
  5. A theme toggle is permanent toolbar furniture for a preference most people set once. It holds a 34 px slot in the highest-value strip of the window.
  6. The second row is right-aligned with nothing on the left. A toolbar with an empty half reads as a stray cluster floating over the list rather than a bar belonging to it.

1 · One bar the second row folds into the first

The branch becomes a scope chip on the leaf crumb — Git history · main — the way GitHub hangs its branch switcher off the repo. Stats and refresh move into the bar's right cluster. The two ⋯ menus become one, with the theme toggle inside it. Row two is deleted.

What it fixes

  • Findings 1, 3, 5, 6. One overflow, one row, location answered in one place.
  • 14 elements → 12, and a whole row of chrome recovered.

What it costs

  • Measured here: the action cluster goes 302 px → 349 px and the trail gains the 76 px chip. Nothing overflows at any width, but the section name starts ellipsizing at about 880 px.
  • Finding 4 survives: the tallies still sit beside Push and Pull without belonging to them.

Precedent

  • GitHub: branch switcher inline with the repo, one toolbar row.
  • macOS HIG unified toolbar; Linear's single 48 px header.

2 · Counts ride the actions recommended every number is attached to what resolves it

Everything in 1, and then the pills go away. “3 local‑outstanding” is “3 to push”, so it is said once, on Push. What neither button can resolve — conflicts, unavailable threads — becomes one attention chip that filters the list, instead of four tallies that do nothing.

  2. /
  3. / Git history

What it fixes

  • All six findings. 14 elements → 10, on one row.
  • Push and Pull stop being blind: you can see there is work before you click, and how much.
  • The row's only remaining tally is the one no button can clear — so it is the one worth a colour.

What it costs

  • Push/Pull change width as counts change. Pin the badge slot to a min-width so the bar does not twitch.
  • The per-status breakdown moves one click away, into the Push/Pull review that already lists it.
  • Squeeze it and the leaf gives way before the chip does — right order, wrong ending: measured at 700 px “Git history” collapses to zero instead of ellipsizing. Floor it, or drop the section crumb to its icon.

Precedent

  • Fork, Tower, GitHub Desktop: ahead/behind badged directly on the sync control.
  • VS Code status bar: ↑2 ↓1 on the sync item, never as a separate readout.

3 · Keep two rows but make the second one a real toolbar

The conservative option: nothing moves between rows. The path bar loses its duplicate ⋯ and its theme button; the second row gains a left anchor, a total, and a closing rule, so it reads as the list's own toolbar instead of a cluster floating above it. This is the Jira / Linear list-header pattern.

4 · Quiet the floor — only what cannot live anywhere else

One bar holding location and the two verbs. Refresh is ⌘R and a menu item; the tallies move down onto the groups they describe, where they are contextual instead of aggregate. VS Code's view header, taken to its conclusion.

  3. / Git history

What it fixes

  • All six, and then some: 14 elements → 8.
  • Counts become answerable — “3 in this commit”, not “3 somewhere on this page”.

What it costs

  • No page-level total at a glance; you read the groups instead.
  • Refresh is discoverable only by menu or shortcut. Needs auto-refresh on window focus to be honest.

Precedent

  • VS Code view headers; Xcode's navigator. Chrome earns its place or leaves.
  • The biggest behaviour change of the four — worth prototyping before committing.
