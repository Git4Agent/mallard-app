1 · Why the status icons are gone ProjectActivityPage.tsx:1119

The row only draws a badge when both a comparison entry and a storage name exist — syncEntry && storageName ? <SessionSyncIndicator/> : … : null. Five ordinary situations fail that and render null: no storage linked (:1897), no provider profile bound (same branch), the comparison threw (:1913), a refresh is in flight (:1927 nulls it before every reload), or the session has no matching entry at all — view-only and unsupported-provider rows never appear in comparison.entries.

Then the 18 px box is styled on the badge itself (RetroTheme.css:1792), so with no badge there is no box, and everything after it slides 26 px left. Not a regression — the identical conditional is at HEAD:ProjectChatHistoryPage.tsx:1061.

The dashed line is where line 2 indents to (--sync-history-row-text-offset: 26px). In i it lands on the title; in ii and iii on nothing.
The rework added a second misalignment. Measured title offsets: HEAD is 38px on every row linked, 12px on every row unlinked — wrong as a whole, but consistent. The working copy is 66 / 106 / 100px, because each row is its own grid and the pill is as wide as the name it holds — Codex vs Claude Code vs Gemini CLI. The titles no longer line up with each other inside one list.

2 · Completing the status vocabulary

The eight badges today all answer “how does this stand against storage?”. Nothing answers “there is no answer yet” — the state a fresh project, a refresh, and a failed comparison are all in. Three neutral additions close the set, so every row carries exactly one badge and the slot is never empty. They stay --text-3: a colour would claim a verdict, and on an unlinked project this badge is on every row.

Contrast against --surface-row: 3.31:1 light, 3.75:1 dark — both clear the 3:1 WCAG 2.2 bar for non-text graphics.
To decide: unavailable is #85878e and untracked is --text-3. Those greys sit close and only the glyph — a minus bar vs a hollow box — separates them. Leave it, or move unavailable onto the warm axis so a cool grey stops being the odd one out?

3 · The redesigned row

Still two lines. Line 1 is identity and controls, line 2 is readout — the split the row already has. Four changes:

A · The badge is never absent, so its box is never empty. That is the whole fix — the slot already had a pinned 18 px width; what it lacked was something to put in it. Line 2’s indent then derives from that width (calc(--row-icon-size + --row-title-gap)) instead of being a 26 px magic number kept in sync by hand. As shipped: badge at 12 px and title at 38 px on every row, measured in a browser against the real stylesheets.

B · The provider logo goes back on the open button, as in HEAD — the OpenAI knot opens Codex, the Claude mark opens Claude Code. The uppercase pill goes away with it. On rows that cannot be opened the mark still renders, dimmed and inert, so the row keeps its identity.

C · The location line goes away. “On this Mac” was on every row of an unlinked project and never varied; on a linked one the badge already encodes it, and its tooltip still spells out the phrase.

D · One control cluster. Debug and the transcript chevron move off line 2 and join the cluster — fixed width, absent controls keep their slot, so the right edge is a column too. Line 2 becomes pure readout, nothing clickable, with the stamp closing it at the card edge.

Row 4 is the case to look at. It is a Gemini CLI session — a provider Mallard has no art for. Providers are an open registry (types.ts:79: “never holds a fixed provider array”, and ProviderDescriptor has no icon field), so a bare key→icon map leaves unknown providers blank — §1’s bug moved one column right. The fallback is a monogram off display_name, which the backend always sends.
Row 3 cannot be opened (remote-only, Pull to open): its Claude mark is dimmed rather than hidden, which is the only reason putting identity on the button works at all.
The Claude mark is still a placeholder. It is an eight-ray tapered burst — vector, not pixel art, and geometricPrecision rather than the sheet's crispEdges, because unantialiased diagonals shatter. The ChatGPT knot makes the same call. It needs the canonical geometry and its own THIRD_PARTY_NOTICES.md entry before it ships.
