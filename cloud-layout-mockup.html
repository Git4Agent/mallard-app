Three ways to lay out the cloud site

Same palette, type, and ink boxes as the desktop app; same content: the HorrorGame repository seeded on staging, pushed by Rika321. Each direction shows the repository page, the listing where it differs, and a session excerpt. The controls above switch every board at once, so a shade or theme can be judged inside each layout rather than on a swatch.

Only the artboards differ. Buttons, pills, prompt tiles, and the timeline are the shipped components.

A Hub the GitHub / Hugging Face convention

A repository header with underlined tabs, a main column for what the version holds, and a facts sidebar for who pushed it, when it was released, which providers it carries, and how big it is. Every developer already knows where to look, and the same frame carries History, Members, and Settings for collaborators.

  • Familiar. Tabs and a right rail are the shape of GitHub, GitLab, Hugging Face, npm.
  • Facts leave the header. The pill row shrinks to class and visibility; everything else sits in the rail.
  • Listing gets filters. A left rail with counts replaces three dropdowns.
  • Needs width. Below ~900px the rail drops under the main column.

C Reader the shared-link convention

What a public link is for: one reading column, a slim header, hairlines instead of boxes, larger type. The shape of a ChatGPT or Claude share page and of a Notion public page. The ink boxes survive on the things you press: buttons, the prompt tile, the theme switch.

  • Best on phones. The column is the page; nothing reflows.
  • Fastest to read. A transcript at 14.5px in a 720px measure.
  • Least chrome. The repository name and who pushed it are the whole header.
  • Least Mallard. The tile grammar is gone; collaborator tools need a second layout.

S Shade how thick the cast shadow sits

The desktop casts 2px in a muted ink. The site can afford more because its tiles are larger and sit alone on the gutter. Buttons and prompt tiles keep one step less than the tile they sit on, so the small things never look heavier than the big ones.

Reads as a rule more than a shadow at site scale.

Where I would land

A for repositories and the listing, C's measure for transcripts. Repository pages carry collaborator tools, so they want the tabbed hub; a session link is mostly opened by someone who was sent it, so it wants the reading column. The two share the top bar, pills, and tiles, so it is one site, not two.

Shade at 3px, soft ink, with controls one step lighter. That is the "slightly thicker than the app" you asked for without turning every card into a poster. B is the right answer if the site should feel like the app above all; it costs anonymous readers the most chrome.
